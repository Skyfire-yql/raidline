# 界面精简与职业技能选择

## 基本信息

- 优先级：P1
- 状态：已完成
- 提出时间：2026-08-04
- 目标版本：Raidline 精简版

## 背景

现有工作台同时展示战报导入、伤害、减伤和治疗压力等大量信息，影响手动排轴的主要流程。技能目录一次展开所有职业技能，也不符合从职业定位技能的操作习惯。

## 目标

把产品收敛为机制说明与职业技能排轴工具，让用户打开新计划后可直接配置 20 人团队，按职业找到技能并完成分配。

## 使用流程

1. 用户创建空白计划，获得 20 个可编辑成员席位。
2. 用户为成员填写职业，在技能页先选择职业、再选择该职业技能。
3. 用户添加机制的时间、名称和说明，并把技能分配到成员轴。
4. 用户保存、分享或导出排轴。

## 功能要求

- 必须实现：移除 WCL 的首页入口、编辑器入口、接口和实现代码。
- 必须实现：机制编辑器只显示时间点、名称、说明和阶段。
- 必须实现：编辑页、时间轴和只读页不显示伤害、治疗缺口、治疗需求或压力结果。
- 必须实现：技能采用“职业 → 该职业技能”两级选择，不展示跨职业完整技能列表。
- 必须实现：分配编辑时，技能列表按所选成员职业过滤；旧的错误职业分配仍可显示以便修正。
- 必须实现：新计划默认生成“成员 01”至“成员 20”，职业保持待选择。
- 希望实现：内置预设只包含常见机制名称与说明，不包含真实或示例伤害数值。
- 本次不做：删除旧计划中的伤害、减伤或 WCL 来源字段；这些字段继续兼容读取与保存。

## 界面与交互

- 首页只保留创建空白计划、预设和最近计划。
- 技能页未选职业时仅显示操作提示；选择职业后显示一个技能下拉框与当前技能摘要。
- 时间轴的机制卡片显示名称和说明，说明过长时截断并可通过悬停查看。
- 手机端沿用现有抽屉与横向滚动能力。

## 数据与规则

- 默认成员 ID 在单份计划内固定为 `member-slot-01` 至 `member-slot-20`，避免 Worker 模块初始化期间调用随机数。
- 未选择职业使用空 `classSlug` 和中性色；选择职业后应用对应职业色。
- 旧计划不自动补足或裁剪到 20 人。
- 已移除的 WCL 路由返回 404。

## 验收标准

- [x] 首页和编辑器中无 WCL 入口，旧 WCL 接口返回 404
- [x] 新计划包含 20 个职业待选择的成员席位
- [x] 未选职业时不显示技能，选职业后只可选择该职业技能
- [x] 机制编辑与只读展示不包含伤害、治疗缺口或压力计算
- [x] 内置预设不包含伤害数值
- [x] 桌面端和手机端均可正常使用
- [x] 相关测试、构建和私有发布验证通过

## 验收结果

- 单元测试覆盖默认 20 人、空职业与职业技能过滤；接口测试确认旧 WCL 路由为 404。
- TypeScript、ESLint、16 项核心测试、生产构建及接口集成测试全部通过。
- 真实浏览器验证桌面与 390×844 手机视图：成员抽屉、职业→技能选择、技能分配和精简机制表单均可正常操作。
- 页面检查未发现 WCL、伤害、压力、治疗缺口或治疗需求文案，浏览器控制台无错误。
