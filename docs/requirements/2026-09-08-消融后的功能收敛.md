# 消融后的功能收敛

用户于 2026-09-08 确认。本文件覆盖 vNext 和较早文档中与以下决定冲突的内容；当前尚未进入分发测试，不兼容旧测试格式。

## 当前规则

- 玩家技能安排以成功施法对应的开始时间为准。瞬发及没有前置读条的引导使用成功事件起点；读条技能缺少匹配开始记录时不导入。失败、取消或只有被动效果的事件不能生成安排，反魔法领域的成功施法例外保持。
- 玩家技能时间轴显示一个从施法起点开始的安排区间，不分别推算忙碌段、GCD 或治疗／减伤覆盖。WCL 的 `observedDurationMs` 记录该次成功施法从开始到观测结束的区间，不是计划内技能配置。
- 技能只有一个全局库。计划只保存 `skillDefinitionId`，不保存技能定义快照、天赋、成员默认变体或单次变体，不提供计划内自定义技能、技能数值修改和目录快照升级。
- 编辑页、只读分享、WCL 预览和发布校验读取当前全局目录；离线编辑读取缓存，没有缓存时使用内置库。内置库位于 `data/player-skills-retail-12.1.json`，全局入口为 `lib/player-skill-library.ts`。更换计划不更换技能库。
- 库中的冷却为已有数据支持的最短固定值，充能取已有配置中的最大值；包括旧变体数组未表达、但技能说明已有明确数值的修正。技能检查仅检查冷却／充能；职业、专精和引用完整性属于结构诊断。网站不验证或调整天赋，不模拟动态减冷却或重置；说明中未量化的修正仍需后续数值核准。
- 日志里的其他实际法术 ID 通过库内 `observedSpells` 提供必要的观测时长，不建立可选变体。显示和 MRT 阅读版均使用全局技能名。
- `TimelineAnchor` 只支持开怪后与阶段开始后的偏移。删除机制不改变任何技能安排或任务，取消机制绑定、继承机制目标和机制覆盖判断。
- 删除成员时同时删除该成员的技能安排，并移除其他对象对该成员的选择引用。执行者因此变空的任务仍保留，可从诊断进入编辑。诊断通过对象类型定位，不按错误代码猜测。
- 删除策略组、小队、分组选择和持久化字段。成员的职业、专精、职责仍用于技能可用性和轨道排序。技能目标保持全团／自己，任务可指定成员。
- 删除手工新增机制实例的入口与构造函数。已有机制仍能编辑、移动、删除；全局机制目录仍由管理后台维护。
- 删除提前提醒设置及其存储、校验、分享显示。游戏内提前提醒交给插件。
- 删除危险度、机制伤害数值、技能效果计算参数、已无消费者的目标人数上限和相关管理表单。机制目标在解除绑定后也不再持久化。
- 删除禁用的痛苦压制旧样板和已退役的玩家提取 profile v1；注册表只保留当前修订 v2。当前 schema v1 的合成边界 fixture 是现行测试，不是旧版兼容实现。
- 删除基于历史自动文案的隐藏过滤。技能安排的备注和任务文字直接显示用户存储的内容；机制时长输入旁不再显示观测来源说明。
- 手机收起侧栏时为按钮预留 28px，侧栏不覆盖时间轴。

## 存储与兼容性

本次是严格 schema v1 在分发前的破坏性收敛，版本号不建立兼容分支。旧字段直接被拒绝，不迁移或补字段。浏览器使用新的 `raidline` IndexedDB 命名空间（版本 1），不打开旧测试数据库，也不自动清除用户旧数据。

技能库升级会同步影响所有计划的技能名称、冷却和默认展示时长，也会影响只读分享。计划内容哈希不包含全局技能库；机制定义仍是计划快照，WCL 原始观测区间仍是事件事实。编辑仍只保存本地，发布／覆盖／删除仍为显式动作，分享 ID 16 位、编辑 ID 4 位保持。
