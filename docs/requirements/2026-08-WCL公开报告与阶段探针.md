# Raidline WCL：公开报告、阶段探针与正式服转换

## 目标

建立最小、真实、可替换的 WCL 只读边界：读取公开报告和 Boss fight，确认史诗难度与精确 `encounterID`，再加载唯一匹配的已发布 encounter profile 与独立全局玩家技能 profile，分页读取所需事件并生成匿名导入预览。只有用户显式勾选后，机制、匿名槽位、按核准规则确认的技能和团队增益背景才进入浏览器本地新计划。

当前 Vashnik 真值为正式服 `encounterID=3455`、`retail-12.1`、profile v3。仓库不注册该 Boss 的 PTR encounter、历史 profile 或旧时间轴 preset。完整样本和事件决定见 [正式服 Vashnik](../Vashink.md)。

## 固定决策

- 只接受 WCL 零售官方区域域名上的 HTTPS `/reports/{reportCode}` 链接，以及空、正整数或 `last` 的 fight 参数。
- 浏览器只调用 Raidline 的 `/api/wcl/reports/probe` 与 `/api/wcl/reports/import-preview`。WCL client secret、Basic 凭据和 access token 只存在于服务端运行时。
- 服务端通过 OAuth client credentials 调用可配置的 WCL token 与 GraphQL endpoint；token 只在进程内缓存。
- 请求任何 profile 事件前，必须确认 fight 元数据、史诗难度和 `encounterID`。非史诗输入不能创建快照、草稿或计划。
- Encounter profile 按 `encounterID + gameVersion + profileVersion + published` 精确选择。没有匹配项时返回“尚未配置”，禁止按技能名、spell ID 或其他 Boss profile fallback。
- Boss 机制、阶段信号、敌方事件选择、配对与去重属于 `EncounterConversionProfile`。玩家个人减伤和治疗技能只属于独立、版本化的全局 `PlayerSkillExtractionProfile`。
- WCL `phaseTransitions` 是阶段基准；缺少官方阶段时只生成 `P1@0`。痛饮、喷泉循环或其他内部状态不得被猜成官方阶段。
- 探针与导入预览不做服务器写入；不返回原始事件、玩家姓名、敏感头、服务端快照或导入草稿，也不写数据库、分享或目录。
- WCL 快照和导入草稿保留毫秒；复制到当前整秒 plan v1 时使用 `floor(atMs / 1000) * 1000`。

## 当前正式服 Vashnik v3

第 4 步最新实施范围与核验限制见 [全局玩家技能 v1](../player-skill-extraction-v1.md)：不请求或读取角色名；多职业同时覆盖；非自身单体减伤／治疗与神圣壁垒不纳入；本轮只建新计划，不合并、不对比。

- 证据集：9 场公开史诗击杀，覆盖 384.229–448.991 秒；同报告另复核 102 次史诗灭团 Pull。
- 元数据门槛：所有击杀均为 `encounterID=3455`、`difficulty=5`、`kill=true`、WCL `gameVersion=1`、`logVersion=17`。
- 阶段：9 场击杀的官方 `phaseTransitions` 均为空，因此稳定转换为单一 `P1@0`。
- Profile：9 个机制定义、10 条采集规则、13 条转换规则。
- 时间轴机制：毒性蒸汽、滴毒之牙、瘟疫泡沫/浪潮、痛饮、恶性催化剂/催化胆汁、冥河感染、爆炸感染、恶念、虹吸感染。
- 失败与关系校验：恶性爆发 `1280189`、漏接胆汁 `1282616`、周期 Tick、派生爆发、辅助光环及死亡事件不生成额外正常时间轴机制。
- 虹吸感染 `1295224` / 鲜血虹吸 `1295229` 是唯一未在当前 111 个 Pull 中观察但经用户明确批准保留的例外；当前公开打法统一采用火泉与影泉。

## 事件收录原则

- 只有时间和语义足够稳定、且需要玩家处理的事件才生成时间轴对象。
- 同一轮多目标光环、AOE 或伤害按人工确认窗口聚类，不能为每名玩家生成一条 Boss 机制。
- 同一机制的连续处理阶段使用一个定义和一个 occurrence，通过 `cast-start`、`impact`、`end` 表达，不重复创建机制。
- “生成时间轴”与“可用于失败校验”彼此独立。失败结果和关系事件可以保留为 validation/replay，但不能冒充正常机制。
- `begincast → cast` 只表示日志中的反应区间；插件提前量不从日志倒推。

## 本地研究与安全

`scripts/wcl-download.ts`、`scripts/wcl-review.ts` 与 `scripts/wcl-convert.ts` 只用于开发者显式指定输入的本地研究。完整事件、聚合审查材料和草稿只能写入被 Git 忽略的 `work/`，不得进入产品 API、fixture、计划或提交。正式调研优先使用官方 WCL v2 API；兼容研究源不是生产依赖。

测试 fixture 必须匿名、聚合且最小化。不得读取、输出或提交 `.env`、secret、access token、玩家姓名或原始大响应。

## 验收

- 严格解析 WCL 链接并拒绝伪造域名、HTTP、异常 report code 和异常 fight。
- 认证、报告、fight、阶段和事件分页失败返回可区分错误且不泄漏凭据。
- Vashnik 正式导入只选择 encounter 3455 / profile v3；profile registry 中该 Boss 只有这一版。
- 史诗门槛、单一 `P1@0`、复合机制、感染聚类、失败事件不建轴和虹吸感染例外均有匿名单元测试。
- API 响应和 Git 状态中不出现原始日志、玩家姓名、敏感头、清洗快照或导入草稿。
